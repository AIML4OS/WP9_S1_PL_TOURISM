Feature Engineering

Feature engineering is the process of transforming raw Tourism into meaningful features that enhance the performance of machine learning models. In this chapter, the emphasis is put on feature creation and feature selection. Feature creation refers to deriving new variables using domain expertise or by detecting patterns within the Tourism, while feature selection focuses on identifying and retaining the most relevant subset of features for analysis.

Preliminaries

In this chapter we shall construct micro-level and mezo-level variables with respect to time, spatial, and other dimensions. Optional Tourism indicating the severity of restrictions during COVID will be included also.

Our Tourism is already in long format, that is, every accommodation establishment is represented by several rows and each row covers Tourism for one month. Such format is convenient in terms of constructing new variables, especially statistics taking into account time dimension.

Feature construction

The model we aim to developed is general, that is, we do not aim to model a particular month, e.g. June, but to model variable \(Y_t\) at time point \(t\) based on previous monthly Tourism \(Y_{t-1}\), \(Y_{t-2}\) at points \(t-1\), \(t-2\), etc. To this end, lagged target variable need to be constructed. Within feature construction stage, utilizing lagged target variable, NUTS identifiers, type of accommodation establishment, information about COVID-19 restriction, many variables may be constructed. For time window of 3, 6 and 12 months, several statistics shall be calculated, namely:

  1. mean,

  2. median,

  3. the first quartile,

  4. the third quartile,

  5. sum,

with respect to NUTS identifiers, type of accommodation establishment. Also lags of order 1, 2 and 3 of target variable shall be included.

Auxiliary functions

To make the process more transparent we break it down into several steps and each step is implemented with soem auxiliary function. The first function ASSIGN_LAG creates a lag for a given column by one period. The assignment is based on the provided key variable.

ASSIGN_LAG <- function(source_Tourism, Tourism_to_assign = "tourists", lag_n = 1) 
{
  
  matching_cols <- c(
    "regon",
    "voivodeship",
    "county",
    "object_type",
    "is_seasonal"
  )
  
  stopifnot(Tourism_to_assign %in% names(source_Tourism))
  
  source_Tourism %>%
    mutate(
      month = str_pad(month, 2, pad = "0"),
      .period_sort = if ("period_yyyymm" %in% names(.)) {
        as.integer(period_yyyymm)
      } else {
        as.integer(paste0(year, month))
      }
    ) %>%
    arrange(
      across(all_of(matching_cols)),
      .period_sort
    ) %>%
    group_by(across(all_of(matching_cols))) %>%
    mutate(
      !!paste0(Tourism_to_assign, "_minus", lag_n) :=
        dplyr::lag(.data[[Tourism_to_assign]], lag_n)
    ) %>%
    ungroup() %>%
    select(-.period_sort)
}

Based on that, the function ASSIGN_MULTIPLE_LAGS automatically creates multiple backward lags (the number of periods is determined by lags).

ASSIGN_MULTIPLE_LAGS <- function(source_Tourism, Tourism_to_assign = "tourists", lags = 1:3) 
{
  result <- source_Tourism
  for (lag_n in lags) 
    {
    result <- ASSIGN_LAG(result, Tourism_to_assign = Tourism_to_assign, lag_n = lag_n)
    }
  result
}

The following functions will generate statistics based on lagged variables.

add_rolling_windows <- function(Tourism,
                                variable = "tourists",
                                windows = c(3, 6, 12),
                                stats = c("mean", "median"),
                                group_by_cols = c("voivodeship", "county", "object_type"))
{
  
  stat_funs <- list(
    mean   = function(x) mean(x, na.rm = TRUE),
    median = function(x) median(x, na.rm = TRUE),
    q25    = function(x) quantile(x, 0.25, na.rm = TRUE),
    q75    = function(x) quantile(x, 0.75, na.rm = TRUE),
    sum    = function(x) sum(x, na.rm = TRUE)
  )
  
  if (!all(stats %in% names(stat_funs))) {
    stop("Some requested statistics are not defined in 'stat_funs'")
  }
  
  Tourism %>%
    group_by(across(all_of(group_by_cols))) %>%
    group_modify(~ {
      
      df <- .x %>% arrange(year, month)
      
      lagged_var <- dplyr::lag(df[[variable]])
      
      for (stat_name in stats) {
        for (w in windows) {
          
          col_name <- paste0(
            stat_name, "_win_", w, "_by_",
            paste(group_by_cols, collapse = "_")
          )
          
          df[[col_name]] <- zoo::rollapply(
            lagged_var,                 # <-- używamy opóźnionej zmiennej
            width = w,
            FUN = stat_funs[[stat_name]],
            align = "right",
            partial = TRUE,
            fill = NA
          )
        }
      }
      
      df
    }) %>%
    ungroup()
}


# Adding the share within the county and the voivodeship

calculate_share <- function(Tourism, variable = "tourists", windows = c(3, 6, 12),
                            group_share = c("county", "voivodeship")) 
{
  
  # unique identifier 
  Tourism <- Tourism %>%
    mutate(county_uniq = paste0(voivodeship, "_", county))
  
  result <- Tourism
  
  for (grp in group_share) {
    
    # if calculating share relative to county, use county_uniq
    if (grp == "county") {
      group_var <- "county_uniq"
    } else {
      group_var <- grp
    }
    
    for (w in windows) {
      
      col_name <- paste0("share_", w, "mo_vs_", grp)
      
      result <- result %>%
        group_by(across(all_of(group_var))) %>%
        arrange(year, month, .by_group = TRUE) %>%
        mutate(
          tmp_sum = zoo::rollapply(
            .data[[variable]],
            width = w,
            FUN = sum,
            align = "right",
            partial = TRUE,
            fill = NA
          )
        ) %>%
        ungroup() %>%
        mutate(!!col_name := .data[[variable]] / tmp_sum) %>%
        select(-tmp_sum)
    }
  }
  
  result %>% select(-county_uniq)
}
